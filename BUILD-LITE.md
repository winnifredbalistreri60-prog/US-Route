# US Route: единая облегчённая сборка

## Один стек вместо нескольких

Сохраняются Java, Android SDK 35, Android Gradle Plugin 8.8.2, Gradle Wrapper 8.10.2 и системный Android WebView. Никаких Flutter, React Native, второго SDK или альтернативного движка сборки не добавлено. Уже используемая AndroidX WebKit 1.12.1 нужна для управления прокси WebView; удалять её ради уменьшения загрузок нельзя без изменения функциональности. Её транзитивные зависимости, включая Kotlin runtime, остаются прежними: Kotlin как язык приложения или отдельный фреймворк не добавляется.

APK не содержит собственных нативных .so-библиотек и не делится по ABI: один файл для совместимых Android-устройств ARM/ARM64/x86/x86_64. Минимум Android 8.0 (API 26); фактическая поддержка прокси зависит также от возможностей установленного WebView. «Универсальный» не означает iOS/Windows и не гарантирует работоспособность на каждом устройстве.

## Сборка без повторных скачиваний

Используйте одну установленную JDK, один Android SDK и стандартный общий каталог Gradle User Home. Путь к SDK задайте в незапакованном `local.properties` через `sdk.dir=/ваш/путь/android-sdk` либо окружением `ANDROID_HOME`. Не создавайте отдельные SDK и GRADLE_USER_HOME для каждой копии проекта. SDK и кэш не входят в исходный архив.

```sh
./build-lite.sh apk    # APK, строго offline
./build-lite.sh check  # APK + JVM-тесты + Android Lint, строго offline
```

Скрипт использует существующий Gradle Wrapper, а не новый сборщик. В `gradle.properties` heap Gradle уменьшен с 2048 до 1024 МиБ, один worker вместо двух, параллельная работа и постоянный daemon отключены. Для процесса JVM-тестов задано 384 МиБ. Это лимиты heap, а не обещание общего потребления RAM: JVM, Lint и системные процессы требуют дополнительной памяти.

Результат: `app/build/outputs/apk/release/app-release.apk`. Сохраняются applicationId `app.usroute`, versionCode 3 и versionName 0.3. Это пересборка той же версии, не новая функциональная версия.

При уже заполненном кэше режим offline исключает обращения за Maven-зависимостями. На совершенно новом компьютере сначала необходимы JDK, SDK 35/Build Tools и дистрибутив Wrapper; первый запуск Wrapper тоже требует его локального наличия. Для осознанного первого заполнения зависимостей:

```sh
ALLOW_DOWNLOADS=1 ./build-lite.sh check
```

Не используйте `--refresh-dependencies` и не очищайте общий кэш без причины. Обновления WebView по-прежнему устанавливаются средствами Android: сборка не встраивает отдельный браузерный движок. Тестовая debug-подпись не подходит для публикации в магазине. На другом компьютере автоматически созданный debug-ключ будет другим; для установки поверх старой версии нужен исходный ключ. Ключи не включены в архив.

## Тестирование без лишних образов

JVM-тесты проверяют логику, но не Android UI, WebView и Keystore. Самый экономный полноценный runtime — уже имеющийся Android-телефон через ADB. Один и тот же APK подходит для телефона и x86_64-эмулятора, отдельная сборка под ABI не требуется.

В текущей среде уже установлен один Android 36 AOSP ATD x86_64-образ и Android Emulator. Второй образ и Android Studio не нужны. Без `/dev/kvm` CPU эмулируется программно; уменьшение окна или RAM не делает такой запуск быстрым. AOSP ATD — тестовый образ, не подтверждение совместимости с пользовательским WebView/Google Play. Если он не загружается за ограниченное время, UI-тест остаётся неподтверждённым; скачивание другого эмулятора само по себе проблему отсутствия KVM не устраняет.

Gradle сохранён: ручная сборка aapt2/javac/d8 потребовала бы самостоятельно поддерживать объединение манифестов, ресурсы и транзитивные AndroidX-зависимости, повышая риск ошибок без устранения необходимости SDK и библиотек.
